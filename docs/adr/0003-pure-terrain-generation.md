# 地形生成是纯函数，Web Worker 只是适配器

区块随玩家流式加载，加载顺序取决于玩家怎么走，而同一个种子必须每次都生成同样的世界。所以地形生成写成纯函数：输入是种子与区块坐标，输出是区块数据，不读相邻区块、不读已加载状态、不留全局变量。跨区块的结构（橡树的树冠越过区块边界）也要以确定性方式解决——按树根所在区块决定，允许写入相邻区块——而不是依赖「邻居已经生成好了」。

把生成搬进 Web Worker 是渲染/宿主适配器的事：核心持有生成器函数，浏览器适配器负责在 Worker 里调用它并异步回填，测试里同步调用同一个函数。

## Considered Options

- **生成时读取邻居区块**：写树、河流这类跨边界结构更直观，但结果依赖加载顺序，同一个种子会因为玩家走法不同而长出不同的世界。
- **核心直接持有 Worker**：核心就不能在 Node 里裸跑，主测试接缝随之失效。

## Consequences

- 地形确定性可以在 Node 中直接断言：先加载 A 再加载 B 与反过来必须一致。
- 生成器不能缓存跨区块状态，某些结构（大型洞穴系统）将来需要用「按确定性种子分区计算」的手法实现。
- 核心保持无依赖，可整体搬进 Worker 或换平台，符合 ADR-0001 关于世界状态与渲染层分离的取向。
