# 跨区块的结构由每个区块自己拉取，而不是写进邻居

ADR-0003 定下地形生成是纯函数，并给跨区块结构定了一种做法：「按树根所在区块决定，允许写入相邻区块」。实现 issue #6（橡树生成）时这条走不通——生成一个区块的函数签名是 `(种子, 区块坐标) → 区块数据`，它只持有一块内存，邻居区块此刻可能还没生成、可能已经卸载、也可能正在另一个 Worker 里。「写入相邻区块」得先有一个跨区块的可写世界，那正是 ADR-0003 要避免的东西。

改成反过来拉：每个区块自己扫一圈「树冠还能伸进来」的树格，把每一棵可能覆盖到自己的树都算出来，只写落在自己区块里的那部分。树的位置与形状仍然只由种子与树根坐标决定，所以两边算出的是同一棵树，合起来就是完整的一棵。

ADR-0003 的决定本身不变：生成不读相邻区块、不读已加载状态、同一个种子每次生成同一个世界。变的只是跨区块结构的实现手法。

## Considered Options

- **按 ADR-0003 原文写入相邻区块**：需要生成器持有一个跨区块的可写世界，结果重新依赖加载顺序与加载状态，等于放弃 ADR-0003 的决定。
- **生成完再补一遍「装饰」阶段**（原版的 feature 阶段那种做法）：要等四邻齐全才能装饰，于是区块有了「已生成但还没装饰」的中间态，流式加载与网格生成都得处理这个状态。本切片不值得。

## Consequences

- 重叠的结构要有确定的先后。橡树按树格坐标字典序写，任何区块算出的相对顺序都一样，所以「谁覆盖谁」是确定的。
- 同一棵树会被最多 4 个区块各算一遍。代价是每个区块多算十几个哈希，可以忽略。
- 结构的水平伸展范围必须是编译期已知的上界（橡树是 `OAK_CANOPY_RADIUS`），扫描范围才能确定。伸展范围不定的结构（大型洞穴系统）仍然要按 ADR-0003 Consequences 里那条「按确定性种子分区计算」另想办法。
- 2026-10-05 补记（第七切片，ADR-0021）：区块外的列要判断时一律调地形模块的三个纯函数查询（群系、地表高度、列顶地表方块），不读邻居区块。拉取的代价因此从「十几个哈希」变成求区块外若干列的密度：树根那一列、判陡坡要看的相邻几列、水塘盆地边缘的几十列。云杉与水塘各有自己的伸展上界；云杉树冠半径不超过 3，否则「树之间只看相邻 8 个树格」的前提不成立。上一条「大型洞穴系统另想办法」见 ADR-0003 的补记。
- 2026-10-05 补记（#79）：三种树共用一套树格与拉取方式，结构的水平伸展上界改为所有树种中最大的树冠半径（`MAX_CANOPY_RADIUS`，云杉的 3），区块按它扩一圈扫树格；判断某棵树伸不伸进区块按这棵树自己的半径。云杉是尖塔形树冠，自下而上 7 层：最下面一层 7×7 去掉四角，往上半径 2、1、2、1，树干顶那一层是 3×3 去掉四角，树干顶之上一格树叶；树干 7 到 9 格。白桦与橡树形状相同，只换原木与树叶。两棵树的最小间距（切比雪夫距离）是两棵树的树冠半径之和加 1，树冠半径在落点阶段按落点那一列的群系定（平原 2，高山与冰雪 3），所以邻格检查只多问一次群系、不问地表高度。最大间距 7 仍小于树格边长 8，「只看相邻 8 个树格」的前提成立。写入顺序仍按树格坐标字典序。
