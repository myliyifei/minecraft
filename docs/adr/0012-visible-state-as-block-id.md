# 方块的可见状态变化用换方块编号表达，不引入方块朝向

熔炉（issue #34）燃烧时正面要换成燃烧中的炉口贴图，熄火后换回来。这是第一种「同一个方块，外观随状态变化」的情形：熔炉里的东西与进度存在方块状态表里（ADR-0011），可网格生成只读区块里一格一字节的方块编号，在 Worker 里跑，看不到状态表。问题是「燃烧中」这件事怎么让网格知道。

定为：**外观不同的状态各占一个方块编号。** 熔炉有两个编号——熔炉与燃烧中的熔炉——共用顶面与侧面贴图，只有正面不同；两者在方块表里是同一种方块状态，所以在两个编号之间切换时状态表里那一条不动。熔炼状态机只在燃烧状态变化时换编号：开始燃烧写成燃烧中的熔炉，燃料烧完且没接续时写回熔炉。写入走 `World.setBlock`，与挖掘、放置同一条路，「哪些区块的网格过期了」那份记录（`takeStaleChunks`）让渲染层重建那个区块的网格，网格生成与 Worker 都不用改。

方块不引入朝向。熔炉与工作台一样，正面固定贴在 −X 与 −Z 两面，放置时不看玩家朝哪儿。

选换编号，是因为它让「这一格长什么样」仍然只由方块编号决定：网格生成、射线检测、区块传输都不必知道状态表。一格一字节还剩两百多个编号，而会变外观的方块只有几种。

## Considered Options

- **网格生成去读状态表**：燃烧与否是状态表里 `burnTicksLeft > 0`，网格按它挑正面贴图。但网格生成在 Worker 与主线程两边跑、直读区块内存（ADR-0011 选状态表正是为了不碰这条路），让它按坐标查一张主线程上的表，就得把状态表同步到 Worker，或者把网格生成里这一格单独拿回主线程算。而且燃料每 tick 都在减，网格不能每 tick 重建，还得另判「影响外观的那部分变没变」——那正是换编号已经做了的事。
- **区块里再加一层每格的附加字节**（朝向、燃烧与否这类小状态）：外观相关的状态都有地方放，朝向也一并解决。但区块内存翻倍，Worker 传输、`ChunkView` 直读、已改区块常驻（ADR-0008）的开销随之翻倍，而目前用得上的只有熔炉这一个布尔。
- **每 tick 按状态对齐编号**（在烧就写燃烧中，不在烧就写熔炉，不管上一 tick 是什么）：外部改了编号也会被纠正回来，但每个熔炉每 tick 都要读一次方块、比一次，而规则本身说的就是「状态变化时换」。只在变化时写，写入次数就是点火与熄火的次数。

## Consequences

- 加一种会变外观的方块（将来的作物生长阶段、发光的红石矿石）：方块表多几行、共用同一种方块状态或都没有状态，由推进它的那个系统在状态变化时 `setBlock`。
- 一件燃料烧完、同一 tick 接着点下一件时不换编号：状态机在同一 tick 里完成接续，熔炉一直在烧，网格不会在两件燃料之间短暂显示熄火的正面。
- 两个编号是同一种方块，凡是问「是不是同一类型」的规则都要把它们归到一起（`baseBlock`）：连锁挖掘里熄火与燃烧中的熔炉连成一片，不因为其中一座在烧就断开。
- 直接写成燃烧中编号、状态里却没在烧的熔炉（调试路径才会这样）保持燃烧中的外观，直到下一次燃烧状态变化。
- 需要朝向的方块（楼梯、面朝玩家放下的箱子）进来时另做决定：每个朝向一个编号会让编号数成倍增长，那时再比较附加字节与编号两条路。
- 火把（第五切片）是第一种需要朝向的方块，定为每个朝向一个编号：地面一个、四面墙各一个，共 5 个。它们是同一种方块，挖掉都掉火把物品，连锁挖掘归到一起（`baseBlock`）。火把只有 5 个朝向，编号够用，附加字节的理由（区块内存翻倍）没有变。楼梯、箱子进来时仍要各自比较。
- 上文「网格生成在 Worker 里跑」「网格生成在 Worker 与主线程两边跑」两处与代码不符：Worker 只生成地形，网格只在主线程上构建。换编号的理由不受影响——网格生成读的是区块里的方块编号，第五切片起还读光照数组（ADR-0017），仍然不读状态表。
- 哪些编号是火把，在火把的支撑表（`torch.ts`）与 `baseBlock` 两处各记一次，由测试对齐。再加一种有朝向的方块时，这两处要一起改。
- 2026-10-05 补记（第七切片）：白桦与云杉的原木、树叶、木板各是新的编号，不引入朝向，原木只竖着放。地表植物与火把一样「下面那格没了随之碎掉」，但它们没有朝向，也没有火把那样的细杆与命中盒：支撑规则拆成一张与几何无关的表（方块 → 贴着哪一格），火把的朝向、细杆与命中盒另留一份，两者由测试对齐。
- 2026-10-06 补记（#80）：支撑表按上一条拆开了。与几何无关的那张表在 `src/core/block.ts`（`supportCell`、`supportHolds`）：每个贴着别的方块的编号记一个偏移与一个条件——五个火把编号贴着的那一格要是不透明方块，四种地表植物贴着下面那一格，那一格要是实心方块。世界换掉一格之后（`World.setBlock`，挖掘与连锁挖掘都经它），只要那一格从不透明变成非不透明、或从实心变成不实心（`mayDetachNeighbors`，这两种条件由支撑表推出），就查上方与四侧贴着它的方块，不再满足支撑条件的在原位变成空气，按掉落表掉东西：火把掉火把，花掉它自己，矮草与蕨什么都不掉。植物的条件定为「实心」而不是「草方块、雪草方块或泥土」：issue 只要求下面那格没了时碎掉，实心与否已经区分了挖掉（空气）与换成水；种花时对下面那格的要求另在放置里判（`isPlantSoil`）。火把那份几何在 `src/core/torch.ts`：`torchSupportCell` 只对火把编号转查支撑表，植物返回 undefined；`torchOnFace`、细杆与命中盒都从支撑表的偏移推出，朝向不另记一份。上一条「哪些编号是火把，在火把的支撑表与 `baseBlock` 两处各记一次」改为三处：支撑表、`torch.ts` 的五个火把编号列表与 `baseBlock`，测试对齐支撑表里认的正好是火把与植物、火把那份只认火把。植物的命中盒（比一整格小的方盒）在 `src/core/plant.ts`，视线与选框经 `partialHitbox` 与火把的细杆走同一条求交。
