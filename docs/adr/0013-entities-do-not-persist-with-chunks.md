# 实体不随区块持久：所在区块没加载时掉落物原地暂停，生物消失

区块卸载之前对实体完全不管。掉落物所在的区块卸载之后，它脚下的方块读出来全是空气（「未加载即空气」，见 `World`），于是它持续下落，直到存活时间到期消失。玩家扔在远处的东西走回去就找不到了。僵尸（#41）进来之后同样的问题更明显：生物会走、会追玩家，走进没加载的区块里就是走在虚空上。问题是「所在区块没加载的实体怎么办」。

定为：**实体只在所在区块已加载时推进。** 「所在区块是否已加载」是实体集合共用的判定，在 `entity.ts` 里，只看水平坐标，小数坐标先向下取整。它有两种形式：

- `isInLoadedChunk(位置)`：一个点所在的区块。僵尸（#41）按它决定消失。
- `isBoxInLoadedChunks(碰撞箱)`：一个碰撞箱在水平方向上涉及的区块是否全都已加载。会与方块碰撞的实体按它判定，理由见下一节。`isInLoadedChunk` 就是碰撞箱缩成一个点时的这个判定。

各种实体按判定结果决定没加载时怎么办：

- **掉落物原地暂停。** 位置、速度、存活 tick 都不变，也不判定拾取；区块重新加载后接着下落、接着计存活时间，轨迹与全程加载时一样。它是玩家的东西，暂停下来走回去还在。
- **生物消失。** 由僵尸 issue（#41）实现。生物是按规则生成出来的，走远了本来就该消失（CONTEXT.md 的「消失」），回来时附近会再生成；为它们保留状态没有意义。
- **经验球不受影响。** 它不受方块影响、只朝玩家飞，不在吸引范围内就停在原地，区块加载与否对它没有区别。

实体本身不随区块存下来：卸载区块这一步不处理实体，不会把它们记进区块或已改区块表（ADR-0008）。暂停的掉落物仍在 `Drops` 的列表里，渲染层照样每帧读到它（ADR-0007）；生物的消失发生在僵尸集合每 tick 推进时，按同一个判定移除，也不在卸载区块那一步。

## 掉落物为什么按碰撞箱判定

只看中心点不够。掉落物的碰撞箱宽 0.25 格，中心还在已加载区块里时，碰撞箱可能已经伸进隔壁没加载的区块，碰撞解算把隔壁那部分读成空气。结果有两种：本来由隔壁方块托着的掉落物掉下去；朝隔壁移动的掉落物移进隔壁本来是实心方块的位置，区块重新加载后卡在方块里，碰撞解算不会把它推出来。

所以掉落物按「碰撞箱在水平方向上按当前速度外扩」的范围判定（`Drop.reach`）：这一 tick 碰撞可能读到的方块都在这个范围里，范围涉及的区块有一个没加载就整 tick 暂停。阻力只会让速度变小，按阻力之前的速度外扩不会少算。碰撞箱正好贴在区块边界上时也算涉及隔壁，多暂停一 tick 没有害处。

## 与方块状态表对照

方块状态表（ADR-0011）已经有同一条过滤规则：熔炉只在所在区块已加载时推进（`World.loadedBlockStates`），卸载期间暂停、不补算。两者暂停的方式一样，但持久的方式不同：

| | 方块状态（熔炉） | 实体（掉落物、生物） |
|---|---|---|
| 存在哪 | 世界的状态表，按坐标索引 | 各自的实体集合 |
| 区块卸载时 | 条目留着：带状态的方块一定是玩家放的，那个区块是已改区块，整块留在内存里 | 掉落物留在集合里暂停，生物从集合里移除（#41） |
| 区块重新加载时 | 接着推进 | 掉落物接着推进；生物按生成规则重新生成 |
| 与区块的关系 | 属于那一格：放下方块时建，方块被挖掉时删 | 不属于哪个区块，每 tick 判定一次所在区块是否已加载 |

方块状态随已改区块常驻，是因为它只在方块被挖掉时删除，方块留着它就得留着。熔炉不会移动，也不与方块碰撞，判定它所在的那一格就够。实体不属于哪个区块：掉落物会滑过区块边界，生物会走过去，把它们存进所属的区块，就得在每次跨过区块边界时从一个区块移到另一个区块。所以实体不存进区块，只在推进时判定一次所在区块。

## Considered Options

- **卸载区块时把里面的掉落物存进区块或已改区块表，加载时放回集合**：暂停的效果一样，但每次卸载、加载都要按区块筛一遍实体，实体跨边界时还要判定它算哪个区块的；而且没改过的区块卸载即丢弃，里面的掉落物要么跟着丢，要么让那个区块也进已改区块表。现在的做法只在推进时判定一次所在区块，实体不需要在区块之间移动。
- **区块卸载时掉落物直接消失**：与生物一致，实现最省。但掉落物是玩家挖出来、扔出来的东西，走远一趟就没了，与「已改区块走回来还在」（ADR-0008）相反。
- **不暂停，让它按当时的方块接着下落**：就是原来的行为，掉进虚空。
- **掉落物只判定中心点所在的区块**：与熔炉、僵尸同一个判定，更简单。但中心点在区块边缘时碰撞会读到隔壁的空气，见上一节。
- **把判定写在掉落物类里**：掉落物直接调 `World.isChunkLoaded` 就够了。但僵尸要用同一个判定决定消失，两处各写一遍取整与区块坐标换算，迟早有一处写错（负坐标不先取整，右移会把 −0.5 算进 0 号区块）。放在实体集合共用的 `entity.ts` 里，与 `stepEntities` 同一处。

## Consequences

- 暂停的掉落物没有上限：玩家到处扔东西、不回去拾取，它们就一直留在列表里，每 tick 各判定一次区块。存活时间只在推进时计，所以暂停的掉落物不会到期。几十个的量级可以忽略；存档那一切片要决定它们写不写盘。
- 暂停的那一 tick 掉落物把上一 tick 的位置对齐到当前位置（`Drop.hold`），渲染层插值时它停在原地，而不是反复重放暂停前的最后一步。
- 渲染层按 `age + alpha` 算漂浮与旋转的相位（ADR-0007），暂停时 `age` 不变，相位每 tick 退回一次，旋转会回跳一小段。暂停的掉落物通常在卸载线以外（默认视距下 144 格以上），这一小段看不出来，这里不处理；将来它出现在近处时，再让 `DropView` 报告是否暂停，由渲染层停下相位。
- 玩家站在已加载区块的边上、掉落物就在隔壁还没加载的区块里（浏览器里 Worker 还没生成好）时，要等那个区块加载了才拾取得到。
- 僵尸 issue（#41）直接用 `isInLoadedChunk` 决定消失，不另写判定。僵尸也要与方块碰撞，但它所在区块一没加载就消失，碰撞箱伸进隔壁的那一 tick 至多多走一步；要不要改按碰撞箱判定，由那个 issue 决定。
