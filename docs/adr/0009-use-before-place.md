# 右键的语义是使用，使用优先于放置

第一切片里右键只做一件事：放置手上的方块。工作台（issue #19）进来之后右键要做第二件事：对着工作台按下去打开工作台界面。两件事同一颗键，得定一个先后。

定为：**右键是「使用」。目标方块是可使用方块（本切片只有工作台）时打开它的界面，不看手上拿的是什么；目标不可使用时这一下才是放置。** 方块表多一列「使用」，写明每种方块右键对着它开哪种界面，绝大多数是「无」。核心收到的指令是 `use()`，不是 `place()`；键位表里那一项叫「使用」。

选「使用优先」而不是「手上有方块就放置」，是因为后者让工作台在拿着方块时打不开——生存流程里玩家几乎总拿着东西，每次开工作台都得先切到空格，而且一不留神就把方块贴在工作台上。原版也是使用优先（潜行才绕过），玩家的手感预期在那一边。

分派放在核心而不是输入层：目标方块每 tick 由核心重算（ADR-0006），右键那一下落在哪一块、那一块可不可使用，只有核心那一 tick 知道。输入层只报「按了使用键」，与它报「按了挖掘键」一样不带判断。

## Considered Options

- **手上有方块就放置，空手才使用**：拿着东西打不开工作台，见上。
- **使用与放置各绑一颗键**：多学一颗键，而原版玩家的肌肉记忆是一颗。设置界面（后续切片）也多一项没人会改的键位。
- **输入层先问核心「目标可使用吗」再决定发哪条指令**：判定跨了两层，而且问的时候读到的是上一 tick 的目标，与指令生效那一 tick 的目标可能不是同一块（ADR-0004、ADR-0006）。

## Consequences

- 熔炉、箱子（第三切片）各在方块表的「使用」一列填自己那一档，核心的分派多一条分支；挖掘与放置的逻辑不动。
- 使用与放置共用一次性输入那条路：下一个 tick 生效，同一个 tick 里按两次只算一下，界面开着时作废。
- 「潜行绕过使用」（潜行时右键对着工作台也放置）等潜行进来再加，是这条分派上的一个额外条件，不改这个决定。
- 打开界面由核心在 tick 里决定，输入层事后才知道。释放指针锁定因此不能只挂在按键处理里，输入适配器每帧同步一次「有界面开着而鼠标还锁着就释放」。抓回锁定仍留在按键处理里——浏览器只在用户手势里放行它。
