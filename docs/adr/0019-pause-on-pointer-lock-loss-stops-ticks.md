# 暂停由指针锁定丢失触发，暂停时 tick 停止

原版按 Esc 打开暂停菜单，单人游戏里世界随即停住。浏览器里 Esc 由浏览器处理：页面收到的不是按键，而是「指针锁定丢失」事件，而且阻止不了。切换窗口、切换标签页、页面隐藏也都会丢失锁定。与此相对，前几个切片里界面模式（背包、工作台、熔炉、死亡画面）开着时世界照旧推进，僵尸照样打玩家。两种「鼠标释放给页面」的状态要不要同一种处理，要定。

定为：**不是输入层自己释放的指针锁定一旦丢失，就是暂停。** 暂停时游戏循环不再调核心的 tick，画面照常画（闪烁按真实时间起伏，与界面模式一致）；进入暂停的那一刻写存档。界面模式要求的释放（按背包键打开背包、对着工作台或熔炉按使用键、死亡）由输入层调用 `exitPointerLock`，调用前记下「这次是自己释放的」，锁定丢失事件到达时读这个记号，不算暂停。判据不读核心的界面标志：按背包键时开合要到下一个 tick 才生效，而锁定当即释放，事件到达时界面标志多半还是假。

界面模式下 tick 不停的规则不变。

## Considered Options

- **界面模式也停 tick**：与原版单人一致，但会改掉已经定下的规则——熔炉在界面开着时照常炼、僵尸照常打——那些规则有自己的测试与理由（打开背包不能当作躲僵尸的手段）。
- **暂停另设一个按键，锁定丢失不管**：玩家按 Esc 之后看到的是鼠标回来了、世界还在跑，再按另一个键才暂停。两步之后才写盘，切换标签页时根本不会按那个键，可能丢失进度的时间最长。
- **暂停时 tick 继续，菜单只是覆盖层**：原版多人服务器的行为，单人没有理由。
- **暂停判据读核心的界面标志**：实现最少，但与按背包键时「开合下一 tick 生效、锁定当即释放」的顺序冲突，打开背包会被误判为暂停。

## Consequences

- 暂停是输入层与循环层的状态，核心不知道它：核心只是没有被 tick。
- 进入世界时加载画面结束后直接处于暂停，显示暂停菜单：加载要等区块与网格，结束时已不在用户手势里，浏览器会拒绝锁定请求。玩家点「回到游戏」才进入第一人称。
- 「回到游戏」在按钮的 click 里请求锁定。暂停在锁定真正生效（`pointerlockchange` 到已锁定）时才解除，循环的累积时间在这时清零，不补 tick；按键与连锁键的状态在这时再清一次。浏览器拒绝请求时（刚用 Esc 退出锁定后有一段冷却），仍停在暂停菜单，提示再点一次。
- 页面隐藏时若有界面开着，先调核心立即生效的「关闭全部界面」指令（ADR-0018），光标物品退回，再暂停。不能走按背包键那条排队的路：暂停之后不再有 tick，排队的开合不会生效。
- 只在暂停与退出时写盘，所以暂停的触发条件就是可能丢失进度的边界：回到游戏之后到下一次暂停之间的改动不在盘上。自上次写盘以来推进过 tick 或有改过的区块时，`beforeunload` 弹出浏览器的离开确认，同时在 `pagehide` 里尽力写一次。
- 进入提示「点击画面开始」去掉：它原来覆盖的场景（页面刚打开、Esc 之后）现在分别由世界列表与暂停菜单接管。
- 死亡画面与指针锁定的关系（ADR-0004 补记里重生立即生效的理由）不变。
