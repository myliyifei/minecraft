# 地形由三维密度决定，地表高度从生成结果里扫出来

前六个切片只有平原：每一列由二维噪声算出一个地表高度，往下填土石。第七切片要做四种群系，高山最高约到 y 200，还要有悬崖、悬垂与低于海平面的洼地。二维高度场每列只有一个地表，做不出悬垂，陡壁也只能是台阶状。

定为：

- **每一格由三维密度的正负决定是不是地形方块。** 密度由群系参数（大陆度、起伏、温度）调制的基准高度减去当前 y，再叠一层三维噪声。为控制开销，密度只在稀疏的格点上采样，格点之间三线性插值，与原版的做法相同。
- **生成分先后几步，每一步只读自己区块内已经写下的结果与纯函数：** 密度决定实心与空气 → 海平面以下的空气灌水，寒冷处的海平面那层换成冰 → 按群系铺地表（上方是空气的每一段实心方块都铺，陡坡露石头）→ 嵌矿脉 → 水塘 → 树 → 地表植物。
- **地表高度不再是噪声的直接输出，而是生成之后一列最高的地形方块。** 树、水塘、植物都以它为准。
- **大海与湖泊里先放静止水。** 流动、桶与重力方块留给流体那一切片，到时再改水的更新规则，生成结果不变。

## Considered Options

- **沿用二维高度场，另外挖洞**：最简单，生成快，现有的 `surfaceAt` 与测试大多不用改。做不出悬垂，高山只能是光滑的鼓包。
- **高度场为主，只在高山叠一层三维噪声**：两套逻辑并存，交界处要额外过渡，复杂度与只用三维密度差不多，好处只在平原生成稍快。

## Consequences

- 地形算法版本从 1 改为 2，第六切片之前建的世界全部不能再进入，只能删除或导出（ADR-0018）。往后地下那一切片加洞穴与岩石层时还要再升一次。
- 树仍按 ADR-0005 从邻近的树格拉取，但树根那一列可能在区块外，算它的地表高度要把那一列的密度从上往下求一遍。跨区块拉取的代价因此从「十几个哈希」变成「几十列密度」，要算进每区块的生成耗时里。水塘同理。
- 出生点的搜索只调群系参数的噪声，不生成区块；找到那一列之后再按密度求它的地表高度。
- 噪声洞穴也写进密度函数（地下那一切片），每一格由三维噪声直接算出是不是空腔，不读邻居。ADR-0003 推给「按确定性种子分区计算」的大型洞穴系统，因此不需要另想办法；只有雕刻器式的峡谷与长隧道仍受 ADR-0005 的上界限制。
- 地形测试与端到端测试里按 `plainsSurfaceHeight` 推算的出生点、树的坐标、列顶高度都要改为从生成结果读，或改用调试句柄查询。
